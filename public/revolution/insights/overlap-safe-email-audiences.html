Build email segments a reviewer can audit

A reviewer should be able to reproduce who qualifies, and see why each person was suppressed. Build the segment so they can.

Wojciech Luszczynski2 min read

Keep eligibility and suppression apart

Start with the population that is allowed to be contacted. Apply consent and suppression from the system of record. Only then add the event or customer-state criteria for this send. The logic and the audience date sit together in one artifact a reviewer can read.

Decide what overlap does

A fictional contact set has 300 onboarding candidates and 140 renewal candidates, 50 of them eligible for both. If onboarding has priority, the send routes 300 to onboarding and 90 to renewal. I show the raw and the assigned counts, so the reviewer can reproduce the split.

Freeze the reviewed definition

I record the filter version, how empty fields are handled and a few synthetic edge cases. The reviewer reads the literal audience definition and the draft together. When a rule or the send date changes, the checks run again.

Make the send easy to judge

Delivered, bounced, unsubscribed and downstream actions get separate rows. A holdout, or another comparison I can defend, helps estimate incremental impact when the volume and the decision justify it. Even if you only audit the send later, the review record explains what changed.

A reviewer can reproduce it

If they cannot rebuild the audience from the definition, they cannot approve it.
