手動入力を必要とする CRM は壊れた CRM だ。人が怠惰だからではなく、インセンティブが間違っているからだ。Rep がデータを入力するのはマネージャーが見るため。マネージャーが見るのはリーダーシップがレポートするため。このチェーンのどこにも、データを入力する人に価値が返ってくるポイントがない。

データ入力は業務の副産物として発生する。追加の作業としてではなく。

### レイヤー 1: Capture

prospect や顧客に触れるすべてが、人の手を介さず CRM に記録されるべきだ。

- メール送信 → ログ
- ミーティング予約 → 参加者とともにログ
- 通話完了 → 時間とともにログ、結果フィールドは call tool から自動入力
- LinkedIn メッセージ送信 → ログ（[Clay](https://www.clay.com/) またはネイティブ連携経由）
- 契約送付 → stage 更新
- 支払い受領 → stage 更新

このレイヤーにギャップがあれば、他の何よりも先に修正する。分析は input の質に依存する。

### レイヤー 2: Enrichment

CRM のすべてのアカウントに、自動更新される最小限の enrichment セットが必要だ:

- 企業属性: 従業員数、売上規模、業種、tech stack
- シグナル: 最近の資金調達、関連部門での採用、製品ローンチ、経営陣の交代
- リレーション: LinkedIn 1st-degree での既存のつながり、紹介ルート

Enrichment はアカウント作成時と毎週のリフレッシュスケジュールで実行される。古いデータはデータがないより悪い: 誤った確信を生む。

### レイヤー 3: Scoring

シンプルな scoring モデルは、scoring モデルがないより良い。3つの input から始める:

1. ICP フィットスコア（理想の顧客プロフィールとの企業属性マッチ）
2. Engagement スコア（チームとのインタラクションの新しさと頻度）
3. Intent シグナルスコア（ウェブサイト訪問、コンテンツダウンロード、測定可能なら製品ページのアクティビティ）

一つの priority score に統合する。毎週更新。毎週月曜朝に rep が見る優先アカウントリストの生成に使う。

モデルは洗練されている必要はない。3つの input の加重合計を四半期に一度手動で調整すれば、直感ベースの優先順位付けに勝つ。

### レイヤー 4: Routing

各 stage 遷移で何が起きるか、明確なルールを定義する:

- 新規 inbound lead → ICP チェック → フィットなら SDR にルーティング、フィットしなければ nurture にルーティング
- SQL 化 → enrichment brief 付きで AE にルーティング
- 21 日以上停滞 → オーナーにアラート、週次 pipeline review でフラグ
- Churn 済み → 90 日後に winback シーケンスにルーティング

Routing ルールは、ルールベースで対応できる 80% のケースでマネージャーの介入を置き換える。マネージャーの時間は、実際の判断が必要な 20% に充てる。

## Build か Configure かの問い

ほとんどの growth ステージの B2B 企業にとって、答えは configure であり build ではない。[HubSpot](https://www.hubspot.com/) または [Salesforce](https://www.salesforce.com/) を正しい automation 設定で使えば、カスタム開発なしでオペレーティングシステムの 90% が手に入る。

Build するのは以下の部分だけ:
- CRM が本当にできないこと（通常はカスタム scoring ロジックか特殊な連携）
- 頻度が高すぎてネイティブの回避策が日常的な摩擦を生む場合

それ以外: 深く configure し、ツールを追加したい衝動に抵抗する。
