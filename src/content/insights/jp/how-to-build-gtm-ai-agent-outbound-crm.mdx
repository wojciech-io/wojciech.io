GTM AIコンテンツの大半は2つに分類される: ChatGPTのpromptのコツか、月500ドルのツール比較で誰も実際に動けないもの。これはそのどちらでもない。

これは私が構築し運用している実働システムの解説だ: outbound research、sequence drafting、CRM enrichment、ICP scoringを処理する4層構造の[Claude Code](https://docs.anthropic.com/en/docs/claude-code) agent stack。[Clay](https://clay.com)なし。[Apollo](https://apollo.io)のenrichment creditsなし。3週間ごとに壊れる[n8n](https://n8n.io) flowsなし。

Claude Codeと、少数の[MCP](https://modelcontextprotocol.io) tools、よく構造化されたCLAUDE.md([starter template](/bites/)を入手)、そして5つのoperator skillsを組み合わせただけだ。

---

## なぜClayではなくClaude Codeなのか

[Clay](https://www.clay.com/)はその目的において優れている: ビジュアルインターフェースと行単位のcreditモデルを備えた構造化されたenrichment pipeline。私も使ったことがある。engineeringリソースなしで大規模なenrichmentが必要なチームにとっては本当に便利だ。

しかし、私の仕事のやり方にとって重要な限界がある:

- 買っているのはenrichment creditsであり、知性ではない。Clayはデータをサードパーティ ([Clearbit](https://clearbit.com/)、[Apollo](https://www.apollo.io/)、LinkedInスクレイパー) 経由でルーティングし、行ごとに課金する。LLM reasoningの層は薄い。
- ビジュアルpipelineは強力だが脆い。複雑なロジックの検査、バージョン管理、引き継ぎが難しくなる。
- 文章を書かない。データを変数に引き出してテンプレートに注入できるが、*なぜこのprospectがこのaccountにとってこの瞬間に重要なのか*についての実際のreasoningはそこにない。

Claude Code、具体的にはMCP toolsを接続したSDK経由のagent loopは、異なるものを構築させてくれる: **コンテキストを読み、fitについて推論し、copyを書き、recordsを更新する**システム、すべてを一度のパスで。知性がプロダクトであり、インフラではない。

## 4層stack

システムには4つのコンポーネントがあり、連携して動作する:

### 第1層: CLAUDE.md: operator briefing

すべてのClaude Code agentセッションは`CLAUDE.md`を読むことから始まる。これはドキュメントではない。briefingファイルだ: 初日のジュニアSDRに渡すものに相当するが、モデルが毎回のrunで読む。

私のものには以下が含まれる:

- ICP定義 (企業属性、技術属性、行動シグナル)
- outreachのトーンとペルソナ (直接的、バズワードなし、operator-to-operator)
- 適格なleadの特徴 vs. 時間の無駄になるケース
- edge caseの対処法 (LinkedInなし、海外市場、inbound vs. outbound)
- 厳格なルール (競合の名前を絶対に出さない、"I hope this finds you well"を絶対に使わない)

CLAUDE.mdはシステムで最も重要なファイルだ。operatorの判断力がここにコード化され、モデルが推測する必要がなくなる。

### 第2層: MCP tools: data accessレイヤー

stackで4つのMCPサーバーを運用している:

**Web search** (Brave MCPまたはExa MCP経由): リアルタイムの企業調査、ファンディングニュース、求人情報、最新コンテンツ。Clayの"waterfall enrichment"ステップを代替。

**Browser automation** (Puppeteer MCP経由): クローラーをブロックするページ用。LinkedIn企業ページ、一部のpricingページ、チームサイズやburn rateに関するGlassdoorシグナル。

**Memory / file system** (Claude Filesystem MCP経由): クライアントファイルの読み書き: CRMエクスポートCSV、sequenceテンプレート、コンタクト済みaccountの記録。

**Custom scoring MCP** (MCP SDKで週末に構築): 構造化されたJSONオブジェクト (企業データ + ICP基準) を受け取り、理由付きのfitスコアを返す。構築が最も難しく、最も価値が高い: agentにrun間で一貫したscoring基準を提供する。

## 実際のrun、ステップバイステップ

新しいaccountリストを処理するときの実際のセッションはこうなる:

1. 50社のCSVを`/clients/acme-corp/`に入れる
2. 実行: `claude /enrich clients/acme-corp/new-accounts.csv`
3. agentが各accountをループ: web search、必要ならbrowser scrape、score、researchファイル書き出し、強化CSVに追加
4. 20分後: fitスコア、priority flags、6以上の全accountのresearchファイルが入った強化CSV
5. トップ10について: `claude /draft [company] v2`、一つずつ、コミット前に各draftをレビュー
6. 送信済みsequencesを`/log`で記録

50 accountリストの合計時間: 約45分の無人agent作業 + 30分の自分のレビュー。同等のClay + copywritingワークフロー: 最低3-4時間、しかもcopyの品質は比較にならない。

## コスト

コストモデルは重要だ。50 account enrichment runあたりの概算:

- Claude API (claude-sonnet-4、現行価格): フルrunあたり約2-4ドル (research深度による)
- MCP tool calls: Brave Search APIは約0.003ドル/クエリ; Puppeteerはセルフホストなのでcomputeのみ
- Custom scoring MCP: 最小限、構造化されたJSONの入出力のみ

Clayとの比較: 意味のあるenrichment credits + LLM rowsを提供するプランで月800-2,400ドル。私のボリュームとuse caseでは、agent stackはそのコストの約5-10%で動作し、reasoningとcopyの層ではoutput品質も上回る。

トレードオフ: 構築に時間がかかった。CLAUDE.md、MCPセットアップ、Skills、scoringツールを合わせて約20時間。その能力がないチームにはClayが正解だ。構築時間を投資できるoperatorにとっては、すぐに元が取れる。

## スターターパック

このコア部分を**Claude Code GTM Agent Starter Pack**としてリリースする: CLAUDE.mdテンプレート、Skills定義、フォルダ構造、scoring MCPソースコード。

GitHubで公開している。無料だ。月400ドルのSaaSラッパーを待つのではなく、自分で構築したいGTM operatorのために設計されている。

パックの前提条件:
- Claude API keyを持っている
- ターミナルでClaude Codeを実行することに慣れている
- 自分のICPをCLAUDE.mdに記入できるほど理解している

この3つが当てはまれば、午後のうちに動作するenrichmentおよびoutreach agentを立ち上げられる。

## 次のステップ

stackに2つの機能を追加予定:

**CRM sync**: HubSpotへの双方向MCPコネクタで、強化されたaccountデータを手動CSV importなしでcontact/company recordsに直接書き込む。

**Signal monitoring**: 軽量なcronで、毎週accountのwatchlistに対して`/score`を実行し、re-engagementトリガー (新規ファンディング、経営陣の交代、関連職種の求人) を検出する。

両方とも作業中だ。安定したらここに記録する。
