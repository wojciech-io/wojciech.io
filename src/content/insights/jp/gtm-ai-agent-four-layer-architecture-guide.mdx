Claude Code GTM Agent Starter Packは4層のアーキテクチャで構成されています。各層にはそれぞれ固有の役割があります。この構造を理解することが、「セッションをまたぐと何もかも忘れるチャットボット」と「実際に機能するシステム」の違いを生みます。

ここでは内部の仕組みを説明します。各層がどう動くか、なぜ分離されているか、どれかを省略したときに何が壊れるか。

## 第1層: CLAUDE.md、operatorとしての立場

CLAUDE.mdはClaude Codeがセッション開始時に最初に読み込むファイルです。エージェントが何ができるかではなく、エージェントが誰であるかを定義します。

GTMエージェントのCLAUDE.mdには次のような内容が含まれます。

```markdown
# Operator識別情報
あなたは[クライアント名]のgrowthチームに組み込まれた上級GTM operatorです。
リサーチ、データ補完、シーケンス実行を通じてoutbound pipelineを加速させることがあなたの仕事です。

# 行動ルール
- 人間の承認なしにメールを送信しない
- ICP定義は /memory/icp.md にあります。leadを評価する前に必ず確認すること
- シーケンステンプレートは /memory/sequences/ にあります。カスタマイズするが、ゼロから作成しない
- 完了したすべてのアクションを /memory/activity-log.md に記録する
```

設計の核心となる原則は「立場の永続性」です。Claude Codeはセッション開始時にCLAUDE.mdを読み込むため、エージェントは毎回同じ運用制約を持ちます。セッションごとに文脈を説明し直す必要はありません。

## 第2層: MCPツール、実際の実行能力

MCPツール（Model Context Protocol）がエージェントに外部システムへの働きかける能力を与えます。テキストを生成するだけでなく、実際に動くことができます。

GTMスタックで使用するツールは以下のとおりです。

- **Brave Search MCP**: 実際のページを読み込むためハルシネーションのリスクなくウェブリサーチができます
- **HubSpot MCP**（またはClayウェブフック）: CRMの読み書き
- **Gmail MCP**: 下書きの作成（CLAUDE.mdのルールに従い、送信はせず下書きのみ）
- **Notion MCP**: 完成したリサーチブリーフを共有ワークスペースに記録

MCPツールなしでは言語モデルです。MCPツールがあれば、企業を調べ、CRMに登録されているか確認し、パーソナライズされたメールを下書きし、作業を記録する、これらすべてを1セッションで完了できるエージェントになります。

## 第3層: クライアントメモリファイル、永続的な文脈

`/memory/`ディレクトリには、エージェントがクライアントについて知っておくべき情報のうち、セッションをまたいでも変わらないものをすべて格納します。

```
/memory/
  icp.md         : ICP定義: 業種、規模、担当役職、失格条件
  sequences/     : バーティカル別、ステージ別のメールテンプレート
  accounts/      : アカウント別リサーチブリーフ（自動生成、人間がレビュー）
  activity-log.md: 完了アクションのログ
  objections.md  : よくある反論と承認済みの返答
```

これがエージェントを「積み重ねていける」ものにする仕組みです。火曜日のセッションでのリサーチは木曜日にも参照できます。先月承認された反論への対処法は、その後のすべてのセッションで使われます。エージェントを再度ブリーフィングする必要はなく、メモリファイルを読み込むだけです。

## 第4層: Operatorスキル、再利用可能なpromptプログラム

スキルは特定のGTM作業を実行するための定義済みpromptプログラムです。Starter Packには5つが含まれています。

**research**: 企業名を受け取り、構造化されたリサーチブリーフを作成します。企業概要、最近のシグナル、想定される課題、ICPへの適合スコアが含まれます。

**enrich**: 担当者名と企業名を受け取り、LinkedInプロフィール、役職、優先事項を特定し、アカウントメモリファイルに追加します。

**draft**: 担当者とアカウントブリーフを受け取り、適切なシーケンステンプレートを使って初回コンタクト用のパーソナライズされたメールを作成します。

**update**: 完了したアクションを受け取り、アクティビティログに記録し、CRMの該当アカウントファイルを更新します。

**score**: leadの一覧を受け取り、ICP定義と照合して各leadを評価し、優先順位をつけたリストを返します。

各スキルには定義されたインプット、アウトプット、ルールを持つ構造化されたpromptがあります。スキルは名前で呼び出します: `/research Acme Corp`。エージェントはスキル定義を読み込み、実行し、構造化された出力を返します。

## なぜ層の分離が重要か

promptに頼ったGTMの多くが機能しない理由は、状態を持たないからです。会話のたびにゼロからスタートします。4層アーキテクチャはこの問題を次の方法で解決します。

- 立場が永続する（CLAUDE.md）
- 能力が実在する（MCPツール）
- 文脈が蓄積される（メモリファイル）
- 実行が一貫している（スキル）

フルoutbound runのコスト、つまりリサーチ、データ補完、下書き、ログ記録、これらすべてのClaude API費用は2〜8ドルです。同等の商用スタック（Clayクレジット、Apolloシート、Outreach）は同じ出力量に対して月200〜500ドルかかります。

差は能力にあるのではありません。運用モデルにあります。
