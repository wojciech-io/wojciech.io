La mayor parte del contenido de GTM AI cae en una de dos categorias: consejos de prompts para ChatGPT, o comparaciones de herramientas de 500 dolares al mes sobre las que nadie puede actuar realmente. Esto no es ninguna de las dos.

Este es un desglose de un sistema funcionando que construi y opero: un stack de agent [Claude Code](https://docs.anthropic.com/en/docs/claude-code) de cuatro capas que maneja outbound research, sequence drafting, CRM enrichment e ICP scoring. Sin [Clay](https://clay.com). Sin creditos de enrichment de [Apollo](https://apollo.io). Sin flujos de [n8n](https://n8n.io) que se rompen cada tres semanas.

Solo Claude Code, un punado de [MCP](https://modelcontextprotocol.io) tools, un CLAUDE.md bien estructurado (descarga el [starter template](/bites/)) y cinco operator skills conectados entre si.

---

## Por que Claude Code en vez de Clay

[Clay](https://www.clay.com/) es excelente en lo que hace: pipelines de enrichment estructurados con una interfaz visual y un modelo de creditos por fila. Lo he usado. Es genuinamente util para equipos que necesitan enrichment a escala sin recursos de engineering.

Pero tiene limites que importan para mi forma de trabajar:

- Estas comprando creditos de enrichment, no inteligencia. Clay enruta datos a traves de proveedores terceros: [Clearbit](https://clearbit.com/), [Apollo](https://www.apollo.io/), scrapers de LinkedIn: y factura por fila. La capa de LLM reasoning es fina.
- La pipeline visual es potente pero fragil. La logica compleja se vuelve dificil de inspeccionar, versionar o traspasar.
- No escribe. Puedes extraer datos a una variable e inyectarlos en un template, pero el razonamiento real sobre *por que este prospect importa para esta cuenta en este momento* no esta.

Claude Code, especificamente el agent loop via SDK con MCP tools conectados, me permite construir algo diferente: un sistema que **lee contexto, razona sobre fit, escribe copy y actualiza records**, todo en un pase. La inteligencia es el producto, no la infraestructura.

## El stack de cuatro capas

El sistema tiene cuatro componentes que trabajan juntos:

### Capa 1: CLAUDE.md: el briefing del operator

Cada sesion del agent de Claude Code empieza leyendo `CLAUDE.md`. No es documentacion. Es el archivo de briefing: el equivalente a lo que le darias a un SDR junior en su primer dia, excepto que lo lee el modelo en cada run.

El mio incluye:

- Definicion de ICP (firmografica, tecnografica, seniales comportamentales)
- Tono y persona para outreach (directo, sin buzzwords, operator-to-operator)
- Como es un lead cualificado vs. uno que hace perder el tiempo
- Como manejar edge cases (sin LinkedIn, mercados extranjeros, inbound vs. outbound)
- Reglas duras (nunca mencionar competidores por nombre, nunca usar "I hope this finds you well")

El CLAUDE.md es el archivo mas importante del sistema. Es donde se codifica el criterio del operator para que el modelo no tenga que adivinar.

### Capa 2: MCP tools: la capa de data access

Ejecuto cuatro servidores MCP en el stack:

**Web search** (via Brave MCP o Exa MCP): para investigacion empresarial en tiempo real, noticias de financiacion, ofertas de empleo, contenido reciente. Sustituye el paso de "waterfall enrichment" en Clay.

**Browser automation** (via Puppeteer MCP): para paginas que bloquean crawlers. Paginas de empresa en LinkedIn, algunas paginas de precios, seniales de Glassdoor sobre tamanio de equipo y burn rate.

**Memory / file system** (via Claude Filesystem MCP): para leer y escribir archivos de cliente: el CSV de export CRM, los templates de sequence, el registro en curso de accounts contactadas.

**Custom scoring MCP** (construido en un fin de semana con el MCP SDK): toma un objeto JSON estructurado (datos de empresa + criterios ICP) y devuelve un puntaje de fit con razonamiento. El mas dificil de construir y el mas valioso: le da al agent una rubrica de scoring consistente entre runs.

## Un run real, paso a paso

Asi es como se ve una sesion real cuando trabajo una nueva lista de accounts:

1. Deja un CSV con 50 nombres de empresas en `/clients/acme-corp/`
2. Ejecuta: `claude /enrich clients/acme-corp/new-accounts.csv`
3. El agent recorre cada account: web search, browser scrape si es necesario, score, escribir archivo de research, agregar al CSV enriquecido
4. 20 minutos despues: CSV enriquecido con puntajes de fit, priority flags y un archivo de research para cada account por encima de 6
5. Para los top 10: `claude /draft [company] v2`, uno a uno, revisando cada draft antes de commit
6. Registra sequences enviadas con `/log`

Tiempo total para una lista de 50 accounts: unos 45 minutos de trabajo del agent sin supervision, mas 30 minutos de mi revision. Workflow equivalente con Clay + copywriting: minimo 3-4 horas, y la calidad del copy no es comparable.

## Lo que cuesta

El modelo de costes importa. Aqui un desglose aproximado por run de enrichment de 50 accounts:

- Claude API (claude-sonnet-4 al precio actual): aprox. 2-4 dolares por run completo dependiendo de la profundidad de research
- MCP tool calls: Brave Search API es aprox. 0,003 dolares/consulta; Puppeteer es self-hosted asi que solo compute
- Custom scoring MCP: minimo, es solo JSON estructurado de entrada/salida

Compara con Clay: 800-2.400 dolares/mes por un plan que da creditos de enrichment significativos mas LLM rows. Para mi volumen y caso de uso, el agent stack corre al 5-10% aproximado de ese coste, con mejor calidad de output en las capas de reasoning y copy.

El tradeoff: llevo tiempo construirlo. Probablemente 20 horas entre CLAUDE.md, setup MCP, Skills y la herramienta de scoring. Para un equipo sin esa capacidad, Clay es la respuesta correcta. Para un operator que puede invertir el tiempo de construccion, se amortiza rapido.

## Quien eres
Eres un agent de B2B GTM research y outreach. Operas en nombre de [Cliente].
Tu trabajo es investigar accounts, evaluar fit y escribir outbound sequences.

## Definicion ICP
**Firmografico:** Tamanio de empresa: [rango] | Industria: [lista] | Geografia: [regiones]

## Que sigue

Estoy aniadiendo dos cosas al stack:

**CRM sync**: un conector MCP bidireccional a HubSpot que escribe datos de account enriquecidos directamente en los records de contact/company sin import CSV manual.

**Signal monitoring**: un cron ligero que ejecuta `/score` semanalmente contra una watchlist de accounts y detecta triggers de re-engagement (nueva financiacion, cambio de liderazgo, ofertas de trabajo para roles relevantes).

Ambos estan en progreso. Los documentare aqui cuando esten estables.
