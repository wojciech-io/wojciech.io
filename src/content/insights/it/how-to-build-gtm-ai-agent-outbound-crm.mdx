La maggior parte dei contenuti GTM AI ricade in una di due categorie: consigli sui prompt per ChatGPT, o confronti di tool da 500 dollari al mese su cui nessuno riesce davvero ad agire. Questo non e' nessuno dei due.

Questa e' un'analisi di un sistema funzionante che ho costruito e gestisco: uno stack agent [Claude Code](https://docs.anthropic.com/en/docs/claude-code) a quattro livelli che gestisce outbound research, sequence drafting, CRM enrichment e ICP scoring. Niente [Clay](https://clay.com). Niente crediti [Apollo](https://apollo.io) per enrichment. Niente flussi [n8n](https://n8n.io) che si rompono ogni tre settimane.

Solo Claude Code, un pugno di [MCP](https://modelcontextprotocol.io) tools, un CLAUDE.md ben strutturato (scarica lo [starter template](/bites/)) e cinque operator skills collegati insieme.

---

## Perche' Claude Code invece di Clay

[Clay](https://www.clay.com/) e' eccellente in cio' che fa: pipeline di enrichment strutturate con un'interfaccia visuale e un modello a crediti per riga. L'ho usato. E' genuinamente utile per team che hanno bisogno di enrichment su scala senza risorse engineering.

Ma ha limiti che contano per il mio modo di lavorare:

- Stai comprando crediti di enrichment, non intelligenza. Clay instrada i dati attraverso provider terzi: [Clearbit](https://clearbit.com/), [Apollo](https://www.apollo.io/), scraper LinkedIn: e fattura per riga. Il layer di LLM reasoning e' sottile.
- La pipeline visuale e' potente ma fragile. La logica complessa diventa difficile da ispezionare, versionare o passare a qualcun altro.
- Non scrive. Puoi tirare dati in una variabile e iniettarli in un template, ma il ragionamento effettivo su *perche' questo prospect e' rilevante per questo account in questo momento* non c'e'.

Claude Code, specificamente l'agent loop via SDK con MCP tools collegati, mi permette di costruire qualcosa di diverso: un sistema che **legge il contesto, ragiona sul fit, scrive copy e aggiorna i record**, tutto in un unico passaggio. L'intelligenza e' il prodotto, non l'infrastruttura.

## Lo stack a quattro livelli

Il sistema ha quattro componenti che lavorano insieme:

### Livello 1: CLAUDE.md: il briefing dell'operator

Ogni sessione dell'agent Claude Code inizia leggendo `CLAUDE.md`. Non e' documentazione. E' il file di briefing: l'equivalente di cio' che daresti a un junior SDR il primo giorno, solo che viene letto dal modello a ogni run.

Il mio include:

- Definizione ICP (firmografica, tecnografica, segnali comportamentali)
- Tono e persona per l'outreach (diretto, niente buzzword, operator-to-operator)
- Come appare un lead qualificato vs. uno che fa perdere tempo
- Come gestire i casi limite (niente LinkedIn, mercati esteri, inbound vs. outbound)
- Regole rigide (mai menzionare concorrenti per nome, mai usare "I hope this finds you well")

Il CLAUDE.md e' il file piu' importante del sistema. E' dove il giudizio dell'operator viene codificato, cosi' il modello non deve indovinare.

### Livello 2: MCP tools: il layer di data access

Gestisco quattro MCP server nello stack:

**Web search** (via Brave MCP o Exa MCP): per ricerca aziendale in tempo reale, notizie sui finanziamenti, offerte di lavoro, contenuti recenti. Sostituisce lo step di "waterfall enrichment" di Clay.

**Browser automation** (via Puppeteer MCP): per pagine che bloccano i crawler. Pagine aziendali LinkedIn, alcune pagine prezzi, segnali Glassdoor su dimensione del team e burn rate.

**Memory / file system** (via Claude Filesystem MCP): per leggere e scrivere file del cliente: il CSV di export CRM, i template delle sequence, il log in corso degli account contattati.

**Custom scoring MCP** (costruito in un weekend con l'MCP SDK): prende un oggetto JSON strutturato (dati aziendali + criteri ICP) e restituisce un punteggio di fit con ragionamento. Il piu' difficile da costruire e il piu' prezioso: fornisce all'agent una rubrica di scoring coerente tra i run.

## Un run reale, passo dopo passo

Ecco come appare una sessione reale quando lavoro su una nuova lista di account:

1. Inserisci un CSV con 50 nomi aziendali in `/clients/acme-corp/`
2. Esegui: `claude /enrich clients/acme-corp/new-accounts.csv`
3. L'agent cicla attraverso ogni account: web search, browser scrape se necessario, score, scrivi file di research, aggiungi al CSV arricchito
4. 20 minuti dopo: CSV arricchito con punteggi di fit, priority flag e un file di research per ogni account sopra 6
5. Per i top 10: `claude /draft [company] v2`, uno alla volta, revisione di ogni draft prima del commit
6. Registra le sequence inviate con `/log`

Tempo totale per una lista di 50 account: circa 45 minuti di lavoro agent non presidiato, piu' 30 minuti di mia revisione. Workflow equivalente Clay + copywriting: minimo 3-4 ore, e la qualita' del copy non e' comparabile.

## Quanto costa

Il modello di costo conta. Ecco una stima approssimativa per run di enrichment di 50 account:

- Claude API (claude-sonnet-4 al prezzo attuale): circa 2-4 dollari per run completo a seconda della profondita' di research
- MCP tool calls: Brave Search API e' circa 0,003 dollari/query; Puppeteer e' self-hosted quindi solo compute
- Custom scoring MCP: minimo, e' solo JSON strutturato in/out

Confronta con Clay: 800-2.400 dollari/mese per un piano che offre crediti di enrichment significativi piu' LLM rows. Per il mio volume e caso d'uso, l'agent stack gira a circa il 5-10% di quel costo, con migliore qualita' di output sui layer di reasoning e copy.

Il tradeoff: ha richiesto tempo per la costruzione. Probabilmente 20 ore tra CLAUDE.md, setup MCP, Skills e tool di scoring. Per un team senza questa capacita', Clay e' la risposta giusta. Per un operator che puo' investire il tempo di costruzione, il ritorno arriva in fretta.
