Der groesste Teil des GTM AI Contents faellt in eine von zwei Kategorien: Prompt-Tipps fuer ChatGPT oder Tool-Vergleiche fuer 500 Dollar im Monat, auf die niemand wirklich handeln kann. Das hier ist keines von beidem.

Das ist ein Breakdown eines funktionierenden Systems, das ich gebaut habe und betreibe: ein Vier-Schichten [Claude Code](https://docs.anthropic.com/en/docs/claude-code) Agent Stack, der Outbound Research, Sequence Drafting, CRM Enrichment und ICP Scoring erledigt. Kein [Clay](https://clay.com). Keine [Apollo](https://apollo.io) Enrichment Credits. Keine [n8n](https://n8n.io) Flows, die alle drei Wochen brechen.

Nur Claude Code, eine Handvoll [MCP](https://modelcontextprotocol.io) Tools, ein gut strukturiertes CLAUDE.md (hol dir das [Starter Template](/bites/)) und fuenf Operator Skills, die zusammen verdrahtet sind.

---

## Warum Claude Code statt Clay

[Clay](https://www.clay.com/) ist exzellent in dem, was es tut: strukturierte Enrichment Pipelines mit visuellem Interface und einem Credit-Modell pro Zeile. Ich habe es benutzt. Es ist wirklich nuetzlich fuer Teams, die Enrichment im grossen Massstab brauchen, ohne Engineering-Ressourcen.

Aber es hat Grenzen, die fuer meine Arbeitsweise relevant sind:

- Du kaufst Enrichment Credits, nicht Intelligenz. Clay routet Daten durch Drittanbieter: [Clearbit](https://clearbit.com/), [Apollo](https://www.apollo.io/), LinkedIn Scraper: und berechnet pro Zeile. Die LLM Reasoning-Schicht ist duenn.
- Die visuelle Pipeline ist maechtig, aber fragil. Komplexe Logik wird schwer zu inspizieren, zu versionieren oder weiterzugeben.
- Es schreibt nicht. Du kannst Daten in eine Variable ziehen und in ein Template injizieren, aber das tatsaechliche Reasoning darueber, *warum dieser Prospect fuer diesen Account in diesem Moment relevant ist*, fehlt.

Claude Code, speziell die Agent Loop via SDK mit angebundenen MCP Tools, laesst mich etwas anderes bauen: ein System, das **Kontext liest, ueber Fit nachdenkt, Copy schreibt und Records aktualisiert**, alles in einem Durchlauf. Die Intelligenz ist das Produkt, nicht die Infrastruktur.

## Der Vier-Schichten-Stack

Das System hat vier Komponenten, die zusammenarbeiten:

### Schicht 1: CLAUDE.md: das Operator Briefing

Jede Claude Code Agent Session beginnt mit dem Lesen von `CLAUDE.md`. Das ist keine Dokumentation. Es ist die Briefing-Datei: das Aequivalent dessen, was du einem Junior SDR am ersten Tag gibst, nur dass es vom Model bei jedem Run gelesen wird.

Meins enthaelt:

- ICP Definition (firmographisch, technographisch, Verhaltenssignale)
- Ton und Persona fuer Outreach (direkt, keine Buzzwords, Operator-to-Operator)
- Was ein qualifizierter Lead aussieht vs. ein Zeitfresser
- Umgang mit Edge Cases (kein LinkedIn, auslaendische Maerkte, Inbound vs. Outbound)
- Harte Regeln (nie Wettbewerber namentlich erwaehnen, nie "I hope this finds you well" verwenden)

Das CLAUDE.md ist die wichtigste Datei im System. Hier wird Operator-Urteilsvermoegen kodiert, damit das Model nicht raten muss.

### Schicht 2: MCP Tools: die Data Access Schicht

Ich betreibe vier MCP Server im Stack:

**Web Search** (via Brave MCP oder Exa MCP): fuer Echtzeit-Unternehmensrecherche, Funding News, Stellenanzeigen, aktuelle Inhalte. Ersetzt den "Waterfall Enrichment"-Schritt in Clay.

**Browser Automation** (via Puppeteer MCP): fuer Seiten, die Crawler blockieren. LinkedIn Unternehmensseiten, einige Pricing Pages, Glassdoor Signale zu Teamgroesse und Burn Rate.

**Memory / File System** (via Claude Filesystem MCP): zum Lesen und Schreiben von Client Files: der CRM Export CSV, die Sequence Templates, das laufende Log kontaktierter Accounts.

**Custom Scoring MCP** (an einem Wochenende mit dem MCP SDK gebaut): nimmt ein strukturiertes JSON-Objekt (Unternehmensdaten + ICP Kriterien) und gibt einen Fit Score mit Begruendung zurueck. Am schwersten zu bauen und am wertvollsten: es gibt dem Agent eine konsistente Scoring-Rubrik ueber Runs hinweg.

## Ein echter Run, Schritt fuer Schritt

So sieht eine tatsaechliche Session aus, wenn ich eine neue Account-Liste bearbeite:

1. Eine CSV mit 50 Unternehmensnamen in `/clients/acme-corp/` ablegen
2. Ausfuehren: `claude /enrich clients/acme-corp/new-accounts.csv`
3. Der Agent loopt durch jeden Account: Web Search, Browser Scrape wenn noetig, Score, Research File schreiben, an angereicherte CSV anhaengen
4. 20 Minuten spaeter: angereicherte CSV mit Fit Scores, Priority Flags und einem Research File fuer jeden Account ueber 6
5. Fuer die Top 10: `claude /draft [company] v2`, einen nach dem anderen, jeden Draft vor dem Commit reviewen
6. Gesendete Sequences mit `/log` erfassen

Gesamtzeit fuer eine 50-Account-Liste: etwa 45 Minuten unbeaufsichtigte Agent-Arbeit, plus 30 Minuten mein Review. Aequivalenter Clay + Copywriting Workflow: mindestens 3-4 Stunden, und die Copy-Qualitaet ist nicht vergleichbar.

---

## Was das kostet

Das Kostenmodell zaehlt. Hier eine grobe Aufschluesselung pro 50-Account Enrichment Run:

- Claude API (claude-sonnet-4 zum aktuellen Preis): ca. 2-4 Dollar pro vollstaendigem Run je nach Research-Tiefe
- MCP Tool Calls: Brave Search API kostet ca. 0,003 Dollar/Abfrage; Puppeteer ist self-hosted, also nur Compute
- Custom Scoring MCP: minimal, es ist nur strukturiertes JSON rein/raus

Vergleich mit Clay: 800-2.400 Dollar/Monat fuer einen Plan, der signifikante Enrichment Credits plus LLM Rows bietet. Fuer mein Volumen und meinen Use Case laeuft der Agent Stack bei rund 5-10% dieser Kosten, mit besserer Output-Qualitaet auf den Reasoning- und Copy-Schichten.

Der Tradeoff: es hat Zeit gebraucht, es zu bauen. Vermutlich 20 Stunden ueber CLAUDE.md, MCP Setup, Skills und Scoring Tool. Fuer ein Team ohne diese Kapazitaet ist Clay die richtige Antwort. Fuer einen Operator, der die Build-Zeit investieren kann, zahlt es sich schnell aus.
