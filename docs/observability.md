# Observability

What we monitor, with what, and why. Decision log included so future-you doesn't re-litigate the stack.

## Stack

| Concern | Tool | Status |
|---|---|---|
| Frontend/runtime errors | Sentry | Partially in place (`sentry.client.config.js` exists in root) |
| Traffic / Core Web Vitals | Cloudflare Web Analytics | Built into CF Pages |
| Uptime / prod-down alerts | Better Stack | Sprint 1+ (urgent mail + optional SMS) |
| Deploy smoke | Playwright (`smoke-prod.yml`) | Sprint 0 stub |
| Agent health | `.agent-state/*/state.md` + daily digest | Sprint 0 |

## Daily digest

A single 8:00 mail to `w.luszczynski@gmail.com` aggregates: items needing decision, what's in progress, what merged, blockers, sprint burndown, deploy status, agent health. Generated by `daily-digest.yml`. Email-only by user decision — no Slack.

## Decision log

- **Why not Grafana/Prometheus?** Overkill for a static site on Cloudflare. No long-running services to scrape, no metrics endpoints worth maintaining. Cost (setup + upkeep) ≫ value. CF Analytics + Sentry + Better Stack cover the real surface.
- **Why Sentry?** Already wired (`sentry.client.config.js`); good DX for frontend error grouping.
- **Why Better Stack for uptime?** Cheap, supports SMS escalation for genuine prod-down, integrates with email-first preference.
- **Why email-only digest?** User explicitly chose mail over Slack for the daily rhythm.

## dev.wojciech.io dashboard

Visual pull-view of the same data (Kanban, agent health, deploy status, decisions queue). Static Astro page, auto-regen on push, behind Cloudflare Access. Spec in `security/access-policy.md`. **Builds in Sprint 1**, not Sprint 0. The dashboard is a reference index; email remains the single source of decisions.
